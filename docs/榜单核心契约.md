# 共享榜单核心契约

入口：`com.dodosupermarket.rank.RankService`（`@Service`）；DTO 为 `bean.dto.RankSettings`；PO 为 `bean.po.RankBoard/RankTag/RankGoodsRef`。异常使用 `RankException.code` 与 `getCode()`。本次不修改 web-starter。

- `settings(long)`、`revision(long)`、`boards(long,boolean)`、`tags(long,boolean)`、`rankedGoods(long,long)`、`associations(long,List<Long>)`、`requireBoard(long,long)`。
- `saveSettings(long,RankSettings)`：`version` 必填；现存榜单 ID 必须完整且各出现一次；标签完整（新标签 id 为 null/0）；priority/enabled/name/boardIds 必填。榜单/标签的 sortOrder 按数组顺序生成。仅修改榜单的 sortOrder/associationPriority/recommendPosition。推荐位置传 null 表示清除。标题、状态、isProd、assets 从数据库读取，本接口永不覆盖。
- `<T> T mutate(long,Long,Supplier<T>)`：旧调用方的 expectedVersion 可选。锁定门店配置行，传入版本时严格比较，在锁内捕获已发布榜单/商品配置值，执行回调，校验全局优先级/推荐位不变量及有变更/新发布的榜单，并在同一事务内将锁定的当前版本递增一次。失败时全部回滚。不得嵌套调用 mutate/saveSettings。回调中的 GenericService CRUD 共用该事务。
- `initializeBoard(long storeId,long boardId)`：在旧版创建（原 CRUD + 商品关系）之后以及旧版发布时，于 mutate 内部立即调用。缺少优先级时分配正整数；保留已启用的自定义归属。无任何归属时添加“综合”。发布时只有已禁用归属，则挂接/启用默认“综合”，但不启用自定义标签。已有自定义归属保持不变。管理端 worker 必须接入此逻辑以保留旧 HTTP API 签名；旧调用方无需提供新字段/版本。
- 管理端删除必须在同一 mutate 回调内移除标签-榜单归属。本共享核心任务不修改管理端/web-starter。
- 已发布榜单的优先级必须为正整数且在已发布榜单内唯一；草稿可共用优先级。推荐位仅限已发布榜单，且 1～3 唯一。新发布或确实被编辑的已发布榜单必须包含非空、唯一、有效的本店商品列表，且至少有一个启用标签。未变更的已发布榜单在后台/标签/无关榜单操作中不依据外部商品目录删除重新校验。允许下线/移除过期榜单。每次变更后都检查全局优先级与推荐位不变量。
- 禁用/删除标签只隐藏分组入口，永不下线已有榜单或抑制关联。`associations` 在过滤请求/可展示商品之前，对所有有效的本店关系计算 row_number；被删除/不可用的候选项单独隐藏，其他商品保持原名次。售罄库存保留。不设整榜无效商品或启用标签门槛。
- `validateGoods(List<RankGoodsRef>)` 检查 goodsId/SKU/sortOrder 的 null/重复。CRUD 服务 `rank.service.RankBoardService/RankTagService/RankGoodsRefService` 继承 GenericService，并配有对应 GenericDAO/XML。
- 错误码：INVALID_ARGUMENT、NOT_FOUND、VERSION_CONFLICT、INVALID_GOODS、INVALID_PUBLISHED_BOARD、INVALID_SETTINGS。

## 范围化校验接入说明

不改变 API 签名。`mutate` 在持有门店锁期间快照业务值（标题、排序、发布状态、优先级、推荐位、图片/颜色、goodsCount，以及每条商品关系的 ID/所属门店/所属榜单/商品/SKU/排序/价格/限购）。比较值可避免将重复的完整设置写入或审计时间戳误判为内容编辑。关系 ID 纳入快照，防止删除后重新导入相同的无效商品绕过严格校验。既有管理端保存/导入必须继续对提交行调用 `validateGoods` 并在 `mutate` 内写入；快照范围化不会移除请求校验。修复榜单时，若其仍保持发布状态，必须使其严格有效；否则应下线（并按需清除推荐位）。仅标签变更时，即使没有启用分组，也保留此前已发布的榜单。

## 新门店缓存兼容

配置行不存在时，`revision(storeId)` 返回初始值 0；该接口保持只读，且不吞掉数据库异常。`settings(storeId)` 在锁定配置行前，于事务内调用具名 `ensureConfig` Mapper。`ensureConfig` 仅依据真实门店行插入；未知门店返回 NOT_FOUND，且不创建配置。新门店以版本 0、默认（null）首页背景、空榜单和空标签开始；后续读取永不复位已保存的版本/背景。缺少表结构或数据库不可用属于部署/运行时错误，绝不静默回退为版本 0。
